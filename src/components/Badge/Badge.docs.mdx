# Badge

Displays a small status or metadata label. Styled with plain Tailwind
utility classes resolved from `variant`/`appearance`/`size` lookup tables —
no variant-authoring abstraction on top, so consumer apps can override any
part of it via `className` (merged with `tailwind-merge`, last conflicting
class wins) rather than fighting a pre-hidden style layer.

## Overriding styles

Because `Badge` resolves its `className` prop through the same `cn()`
merge utility the rest of the library uses, an app-level override always
wins over the variant defaults:

```tsx
<Badge className="bg-purple-100 text-purple-900 border-purple-300 rounded-full">Custom</Badge>
```

## Dismissible badges

Passing `onDismiss` renders a trailing dismiss button (replacing
`rightIcon`, if also supplied) that calls the handler on click:

```tsx
<Badge onDismiss={() => removeTag(tag.id)}>{tag.label}</Badge>
```

## Status dots

`dot` renders a standalone status dot instead of a labeled badge —
`children`, icons, and `onDismiss` are all ignored. Pass an `aria-label`
if the dot conveys meaning on its own (otherwise it's treated as
decorative and hidden from assistive tech).

`withDot` instead renders a small leading dot before `children`, in place
of `leftIcon`, for a "labeled status" badge like "Active".

## Interactive badges

`interactive` turns the badge into a `role="button"` with hover/active
states, a focus ring, and Enter/Space activation for `onClick` — useful
for a removable filter chip that also responds to a plain click. It stays
a `<span>` rather than becoming a real `<button>`, so it composes as a
label everywhere a `Badge` already does; if you need a fully native
button element instead, render your own `<button>` styled with the same
class tables.

## Disabled

`disabled` dims the badge and blocks all pointer/keyboard interaction,
including the dismiss button.

## Composition

`Badge` forwards its ref to the root `<span>` and spreads all native
`<span>` props, so it composes with tooltips and other components in this
library without a separate "as child" API.
