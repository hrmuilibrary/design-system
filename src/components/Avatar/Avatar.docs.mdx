# Avatar

Represents a person or entity as a circular (or square) image, initials, or
icon. Falls back automatically: an image that fails to load (`onError`)
reverts to initials derived from `name`, and no `name` at all falls back to
a generic user icon (or a custom `fallback` node). When `name` drives the
initials, the background color is also derived deterministically from the
name so the same person always gets the same color.

## Sizes

`size` scales the avatar, its status dot, and its edit button together,
from `2xs` through `2xl`.

## Status indicator

`status` renders a small ring-bordered dot (`online` / `offline` / `away` /
`busy`) anchored to the bottom-right corner — or the bottom-left corner
when `editable` is also set, since the edit button then takes the
bottom-right spot.

## Editable (upload overlay)

`editable` renders a small pencil-icon button in the bottom-right corner,
scaled to `size`, that opens a native file picker. Picking a file shows an
immediate local preview (an object URL `Avatar` creates and revokes itself
on replacement or unmount) and calls `onImageChange` with the picked
`File`. The local preview takes precedence over `src` until `src` itself
changes to a new value (e.g. once your upload completes and you pass back
the real remote URL), at which point the new `src` wins and the local
preview is dropped.

`accept` and `maxSizeMB` validate the picked file before it's previewed —
the same matching rules as `UploadProps.accept`/`maxSizeMB`, but always
enforced here (unlike `Upload`, where enforcement is gated behind
`validateFiles`) — validated through the same `validateSingleFile` helper
`Upload` uses internally, so the two components can't drift on what counts
as a valid file. A file that fails validation never updates the preview;
`onReject` is called instead with the `UploadRejection` (a single object,
not an array — `Avatar` only ever picks one file at a time).

The edit button's touch target falls below the WCAG 2.5.8 24×24px minimum
at `'2xs'`/`'xs'`/`'sm'`. `editable` is best suited to `'sm'` and above for
touch accessibility; consumers using it at smaller sizes should be aware
the target is below the recommended minimum.

```tsx
<Avatar
  name="Ada Lovelace"
  editable
  accept="image/*"
  maxSizeMB={5}
  onImageChange={(file) => uploadAvatar(file)}
  onReject={(rejection) => showError(rejection.reason)}
/>
```

`editable` is fully opt-in: when it's unset, none of this preview state or
markup activates, so existing uncontrolled `src` usage is unaffected.

## Fallback order

1. `src` renders as an `<img>` — until it fails to load.
2. `name` renders as initials (max two characters) on a name-derived
   background color.
3. A generic user icon, or a caller-supplied `fallback` node, when neither
   `src` nor `name` is present.

## AvatarGroup

`AvatarGroup` stacks `Avatar` children with a slight negative margin and a
white ring separator, most recent first (`z-index` decreases left to
right). Pass `max` to cap how many are shown; anything beyond that renders
as a `+N` avatar using the same name-derived coloring as a regular avatar.

```tsx
<AvatarGroup size="md" max={3}>
  <Avatar name="Ada Lovelace" />
  <Avatar name="Grace Hopper" />
  <Avatar src="/alan.jpg" alt="Alan Turing" />
  <Avatar name="Katherine Johnson" />
  <Avatar name="Margaret Hamilton" />
</AvatarGroup>
```

## Overriding styles

Both `Avatar` and `AvatarGroup` resolve their `className` prop through the
same `cn()` merge utility the rest of the library uses, so an app-level
override always wins over the component defaults:

```tsx
<Avatar name="Ada Lovelace" className="ring-2 ring-brand-500 ring-offset-2" />
```

## Composition

Both components forward their ref (`Avatar` to the root `<span>`,
`AvatarGroup` to the root `<div>`) and spread all native attributes for
their element, so they compose with tooltips, links, and other components
in this library without a separate "as child" API.
