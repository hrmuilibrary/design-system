# MultiSelect

A chip/token multi-select combobox — the multi-value cousin of `Select`.
Chosen options render as removable chips inline with a type-to-filter
input; a dropdown lists the remaining options. Options can carry an
avatar, a description line and a chip badge, so the same API covers both a
plain tag input and a rich people picker.

## Controlled only

Unlike `Select`, `MultiSelect` has no uncontrolled mode — `value` (an array
of option values, `string | number`) and `onChange` are both required:

```tsx
const [value, setValue] = useState<(string | number)[]>([]);
<MultiSelect options={options} value={value} onChange={setValue} />
```

## Options

Each `MultiSelectOption` is data-agnostic:

```tsx
interface MultiSelectOption {
  value: string | number;
  label: ReactNode;
  searchText?: string;   // matched against when label isn't a plain string
  description?: string; // second line in the dropdown row
  avatarSrc?: string;    // shown on the chip and the dropdown row
  disabled?: boolean;    // non-selectable, dimmed
  badge?: ReactNode;     // small tag on the chip, e.g. "You"
  group?: string;        // heading this option renders under
}
```

## Keyboard interaction

- `↓` opens the dropdown, or moves the active option while it's open
- `↑` moves the active option
- `Enter` selects the active option
- `Esc` closes the dropdown
- `Backspace` on an empty input removes the last removable chip

## Locking and limits

`lockedValues` marks selected values whose chips can't be removed (no `X`
button rendered). `max` caps the number of selections — once reached, the
input disables and the placeholder switches to `Limit {max} reached`.

## Non-searchable mode

Set `searchable={false}` for a click-to-open picker with no text filter —
the input becomes read-only and the dropdown always shows the full
remaining option list under `suggestionsLabel`.

## Rich labels

`label` accepts any `ReactNode` — an icon, a two-line layout, translated
rich text — not just plain strings. When `label` isn't a plain string, give
the option a `searchText` so type-to-filter still has something to match
against; without one, that option is excluded from search results rather
than matched against its stringified value. Chips and dropdown rows always
render the full `label` node, not a coerced string form.

## Grouped options

Give any `MultiSelectOption` a `group: string` to render it under a
heading in the dropdown. Options sharing a group must be contiguous in the
(filtered) list — the heading is emitted whenever `group` changes between
consecutive visible options, so a non-contiguous group renders its heading
more than once.

## Loading

`loading` shows a spinner in the trailing edge of the chip row and blocks
opening the dropdown — it does not set the native `disabled` attribute.

## Validation state

`error` (boolean) switches the chip row to the danger border/ring styles;
`errorText` does the same and also renders below the control in place of
`helperText`.

## Label addons

`labelAddons` renders content on the label row, to the right of the label
text and required marker — e.g. an info tooltip trigger. It's rendered as
a sibling of the `<label>` element, not a child, so an interactive addon
never steals focus into the field when clicked.

## Granular add/remove callbacks

`onChange` always fires with the full next `value` array. `onAdd(option)`
and `onRemove(value)` fire alongside it — never instead of it — for
consumers who want to react to a single selection change (e.g. an audit
log) without diffing the array themselves.

```tsx
<MultiSelect
  options={options}
  value={value}
  onChange={setValue}
  onAdd={(option) => track('reviewer_added', { id: option.value })}
  onRemove={(value) => track('reviewer_removed', { id: value })}
/>
```

## Avatars

Options with an `avatarSrc` always show an avatar. Set `showAvatars` to
render one for every option, even those without an image — `Avatar`
falls back to initials (with a color hashed from the name) derived from
`searchText` when present, or from `label` when it's a plain string.
A rich (non-string) `label` with no `searchText` has no string to derive
initials from, so it gets `Avatar`'s generic fallback icon instead.

## Composition

`MultiSelect` forwards its ref to the inner text `<input>`. Its root DOM
node is the wrapping `<div>` (label + chip row + dropdown + helper/error
text), which is where `dataTestId` is applied as `data-test-id`. It
composes with `Avatar` for chip and dropdown-row avatars.
